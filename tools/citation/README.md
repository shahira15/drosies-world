# Citation tooling: single source of truth

`metadata.json` is the **only** place where scholarly facts are entered by hand. Everything else is generated from it:

| Output | Generated by `build_cite.py` |
|---|---|
| `/cite/` page, per-resource citations (APA 7, MLA 9, Chicago, BibTeX, RIS) | yes |
| `cite/drosies-world-bibliography.{ris,bib,enw}` | yes (no hard-coded access dates) |
| `CITATION.cff` | yes |
| `<meta name="citation_*">` + Schema.org JSON-LD on resource pages | yes (between `<!-- cite-meta:start/end -->`) |
| `VERIFICATION_CHECKLIST.md` | yes |

```
python3 tools/citation/build_cite.py     # rebuild everything (idempotent)
python3 tests/citation/validate.py       # static checks (needs PyYAML; uses cffconvert if installed)
```

## What goes where

- **Resources** (titles, URLs, descriptions): `resources.py`. Add a resource only if its page exists.
- **Author, affiliation, ORCID, licence, book DOI, software DOI/version/release date**: `metadata.json`.
- `null` means "not verified / does not exist". The generator omits nulls and never substitutes a guess.

## Rules the generator enforces

1. **No overwriting verified data.** If `CITATION.cff` was not produced by this generator (for example the hand-maintained release file from the software-release work), or it contains a DOI, ORCID, version, release date or licence that `metadata.json` does not, the build **stops with an error**. Copy the verified values into `metadata.json`, then re-run (or pass `--force-cff` deliberately).
2. **No inferred dates.** Only the storybook has a year (taken from its Zenodo citation as already published on the site). All other resources are cited as `n.d.` with the reader's own access date. Copyright years and commit dates are never used.
3. **No invented identifiers.** A software DOI appears on the page, in `CITATION.cff` and in the citable list only after `software.doi` is set in `metadata.json`.
4. **Illustrator attribution** is part of every storybook citation format.

## Adding the software DOI after a release (future)

1. Deposit the release (human-approved) and obtain the real DOI.
2. Fill `software.doi`, `software.version`, `software.date_released`, and `software.title` in `metadata.json`; set `software.release_status`.
3. Run `build_cite.py`. The page gains an "Archived software" section with its own citations, the placeholder card disappears, and `CITATION.cff` gains `doi`, `version`, `date-released`.
4. Add the ORCID the same way (`author.orcid`, full `https://orcid.org/...` form) and the licence (`license`, an SPDX id) once decided.

## Manual verification still required

See `VERIFICATION_CHECKLIST.md` (storybook Zenodo record: author string, date/version, illustrator and rights statement, resource type).
